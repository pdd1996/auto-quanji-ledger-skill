# 合规与安全边界

> 记账应用会接触**个人金融账户信息**，属于**个人敏感信息**。以下边界不是建议，是硬约束。

## 一、绝对不做

| 禁止 | 原因 |
|---|---|
| 抓包 / 中间人还原平台私有协议 | 违反用户协议；情节严重可触**非法获取计算机信息系统数据罪** |
| 模拟登录 / 复用 Cookie / 爬虫 | 同上，且涉及账号密码保管 |
| 用无障碍服务读微信/支付宝界面 | 极易被判定为权限滥用，商店必拒 |
| 服务端接收账单解压口令 | 口令绝不离开用户设备 |
| 代收代付 / 余额 / 提现 | 需要《支付业务许可证》 |
| 信用评分 / 放贷导流 | 涉及《征信业务管理办法》 |

## 二、取件时的硬约束

- **只读**：IMAP `select(readonly=True)` —— 不删除、不改标记、不动用户邮件
- **只按白名单**：只搜白名单发件人，**绝不遍历全部邮件**
- **凭据不落盘**：优先环境变量；若要保存必须提示是明文；**永不打印**
- **最小暴露面**：只取附件；正文只用来提取下载链接
- **本地处理**：解密、解析、分类全在设备内完成；不上传任何账单数据

## 三、口令处理

- 口令**每次导出都变**，由平台经另一通道下发（微信→公众号，支付宝→页面）
- **默认做法**：让用户提供口令（可给多个候选，自动逐个试）
- **默认不做**：主动恢复 / 穷举。本包**已实现**设备端口令恢复
  （`scripts/unlock_bills.py` / `scripts/unlock_pdf.py`），但**默认关闭**：

  | 约束项 | 规则 |
  |---|---|
  | 触发条件 | 用户**明确要求** + 命令行显式 `--consent`；缺一不执行 |
  | 执行位置 | 只在**用户设备**上；服务端永不接触口令 |
  | 开始前 | 必须先打印**代价说明**（脚本内置文本，见下） |
  | 口令去向 | 不打印、不进对话/日志/远端；只写本地文件（明文，带警告头），`--show` 仅供本地终端 |
  | 明确拒绝 | AES / 强加密（zip `compress_type == 99`、PDF V≥4）—— 无捷径，不要假装能解 |

- **代价必须讲清**（这段就是"书面说明"，开始前脚本会原样打印）：
  - 法律上属于处置用户自己的文件，不构成"未经授权访问系统"；
  - 但可能被平台视为**规避技术保护措施**，且**内置恢复逻辑是明确的商店审核风险**；
  - **收益只是省掉用户一次复制**，代价是协议与审核风险 —— 通常不匹配，
    所以默认关闭；对外分发（尤其商店上架版本）应先评估是否移除该工具。
- 量级参考（实测）：ZipCrypto 6 位数字约数秒；PDF（RC4-128）6 位数字约 1–2 分钟；
  AES 不可恢复。

## 四、输出侧

- **剥离身份信息**：preamble 里的姓名 / 支付宝账户 / 微信昵称**一律不进输出**
- **脱敏**：交易对方里形如 `徒***岸`、`x***4` 的已是平台脱敏，保持原样
- **日志**：金额、商户名、邮箱地址不应出现在调试日志里
- **可删除**：提供清除全部本地数据的能力

## 五、对用户的话术

不要说"打通了微信支付宝"——用户会理解成自动同步，预期和合规双重踩坑。

应该说：**「账单导入 + 自动取件 + AI 归类」**。

并且诚实告知能力边界：
- ✅ 能自动化的：取件、解密、解析、去重、分类、洞察
- ❌ 不能自动化的：**在 App 内点"导出账单"**（平台侧无 API）、**拿解压口令**（经另一通道下发）
- ⚠️ 口令丢失是真实场景：可在用户**明确要求**下于设备端恢复（见第三节）。
  对外话术仍以"候选口令自动试"为准，**不主动宣传**恢复能力。

## 六、应用商店审查（若做 App）

| 权限 | 风险 | 应对 |
|---|---|---|
| 通知监听 | 国内需说明场景；**Google Play 基本不允许** | 仅 Android，可关闭，提供完整替代路径 |
| 读短信 | Play 严格限制 | 明确场景 + 逐字说明 |
| 无障碍 | 极易判为滥用 | **坚决不用** |
| 相册/相机 | 相对安全 | 仅用户选图时申请 |

**iOS 与 Android 不要讲同一套话术**：iOS 无法监听通知，主打"账单导入 + 洞察"。
